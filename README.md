# Тренажёр слов

Человек не выбирает колоды, уровни и интервалы. Он говорит, зачем ему слова, — и получает
готовый набор и расписание повторений.

## Поток

1. Человек одной фразой пишет, зачем ему слова.
2. Сервис задаёт уточняющие вопросы по одному, пока задача не станет конкретной. Пока известны
   не все три вещи — язык, ситуация, какой смысл не выражается — дальше не пускает и говорит,
   чего не хватает.
3. По конкретной задаче модель предлагает 12 слов, к каждому — пример фразы. Человек подтверждает.
4. Из набора получаются карточки двух видов: «закончи фразу» и «скажи то же другими словами».
5. Тренировка: карточка → человек отвечает про себя или вслух → «справился» / «не справился».
   Больше сервис ничего не оценивает.
6. Дату следующего показа считает FSRS (`ts-fsrs`).
7. При следующем заходе сервис сам даёт то, что пора повторить, и говорит, когда прийти снова.

Слова и примеры приходят от модели под задачу человека, а не из готовых словарей. Язык любой,
включая родной.

## Запуск

```sh
npm install
npm start          # http://localhost:5173
```

Нужен ключ Anthropic API. Создай файл `.env` рядом с `server.js` и положи в него одну строку:

```
ANTHROPIC_API_KEY=твой-ключ
```

`npm start` подхватит его сам (`node --env-file-if-exists=.env`). Можно вместо этого
экспортировать `ANTHROPIC_API_KEY` в окружении.

Открывать удобнее с телефона: `http://<ip-компьютера>:5173` в той же сети.

## Тесты

```sh
npm test             # поведение по HTTP + экран в браузере, без сети и без ключа
npm run test:llm     # качество ответов живой модели — платно, нужен ключ в окружении
```

Тесты написаны по требованиям из `specs/` и работают с приложением снаружи.
Подробности и матрица «требование → тест» — в [test/README.md](test/README.md).

## Как обновляется прод

Только через GitHub Actions и только после зелёных тестов. Push в `main` запускает
`.github/workflows/deploy.yml`: тесты (те же, что на PR) → миграции → выкатка в прод Vercel.
Падают тесты — деплой не запускается. Запуски выстроены в очередь по одному, чтобы старая
выкатка не легла поверх новой.

Своя автосборка прода у Vercel выключена — `git.deploymentEnabled.main: false` в `vercel.json`.
Превью на PR остались: они собираются с веток, а правило касается только `main`.

## Устройство

```
server.js            HTTP: статика + /api/*
lib/claude.js        один вызов модели со структурированным ответом по JSON-схеме
lib/prompts.js       два промпта: уточнение задачи и подбор набора
lib/scheduler.js     обёртка над FSRS; две оценки — справился / не справился
lib/session.js       сборка карточек из набора и очередь на сегодня
lib/store.js         состояние в data/state.json
public/              интерфейс: без сборки и фреймворков
test/                тесты по требованиям из specs/
test-harness/        стенд для тестов: запуск приложения, заглушка модели, часы
```

Состояние лежит в `data/state.json`. `POST /api/reset` очищает его — это способ начать заново.
Лишний заход («пройти слова ещё раз») живёт только в памяти сервиса: сроки он не двигает,
поэтому сохранять о нём нечего — перезапуск возвращает человека к «на сегодня всё».

Модель: `claude-opus-5`. Уточнение задачи идёт на `effort: low` (нужна скорость диалога),
подбор набора — на `medium`. Включён серверный фолбэк на случай отказа модели; если API его
не принимает, вызов автоматически повторяется без него.

## Чего нет в первой версии

Работы без интернета, звука и распознавания речи, оценки ответа моделью, правки набора,
нескольких человек. Всё это сознательно отложено.

## Настройки, которые человек не видит

`lib/prompts.js` — `WORDS_PER_SET` (12 слов в наборе). Набор, не прошедший проверку —
неполный, со словом в пропуске или в подсказке, — считается сорвавшимся подбором.
`lib/scheduler.js` — `NEW_PER_DAY` (12 новых карточек в день) и параметры FSRS.
`lib/claude.js` — `MODEL_TIMEOUT_MS` (90 секунд на весь вызов модели, вместе с повторами;
можно переопределить переменной окружения). Дольше ждать нельзя: на это время экран заперт.
