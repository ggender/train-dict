## 2. Принятые технические решения

### 2.1 Изоляция — копия приложения во временном каталоге, ноль правок продукта

`test-harness/app.js` копирует `server.js`, `package.json`, `lib/`, `public/` во временный
каталог, кладёт рядом симлинк на `node_modules` и запускает приложение оттуда. Продукт сам
выводит каталог данных из своего расположения — значит, пишет во временный файл.

Что это даёт: рабочий `data/state.json` тесты не видят; `.env` во временную копию не
копируется, поэтому тестовый процесс физически не может обратиться к живой модели; продуктовый
код не изменён ни на строку.

Отвергнуто: переменная окружения в `lib/store.js` (правка продукта ради тестов);
бэкап-восстановление рабочего файла (падение прогона оставляет чужие данные на месте рабочих).

### 2.2 Подставная модель

`test-harness/model-stub.js` — HTTP-сервер, отвечающий как Anthropic API на `POST /v1/messages`.
Приложению передаётся `ANTHROPIC_BASE_URL` на него. Различает два разговора по тексту задания
(«подбираешь набор слов» → подбор, иначе уточнение). Режимы: заготовленный ответ, пустой набор,
ошибка, задержка. Пишет журнал полученных запросов — по нему проверяется, что после сброса
прежняя история в модель не уезжает и что задача человека доходит целиком.

Ошибку отдаёт кодом 400, а не 500: SDK не повторяет такой запрос, тест не ждёт лишнего.

### 2.3 Время — через данные

`test-harness/state.js` собирает сохранённое состояние с нужными `due` и `firstSeenAt`:
«просрочено» — час назад, «показано вчера» — 25 часов назад (всегда не сегодня, в любое время
суток), «карточка вот-вот» — через 6 секунд. Единственный тест с реальным ожиданием — авто-
обновление экрана (~7 с).

### 2.4 Инструменты

| Прогон | Раннер |
|---|---|
| Экран и HTTP | `@playwright/test` + Chromium (в проекте лежал `playwright-core` — библиотека без раннера и браузеров) |
| Расчёт сроков | Vitest |

`npm test` = `npm run test:unit && npm run test:e2e`.

Живая модель отменена, поэтому 13 сценариев про качество её ответов закрыты **на границе**:

## 6. Что осталось непроверенным

1. **Соблюдает ли модель правила, которые ей передали.** Без платного прогона — никак.
   Восстанавливается одной командой, если решение изменится: ~$0.6 и 5–10 минут.
2. **Сценарии 4.8 и 4.9 зафиксированы искусственно.** Состояние «карточка вернётся меньше чем
   через десять минут» обычным путём не достигается: окно захода (`lib/session.js:9`) втягивает
   всё, что вернётся в ближайшие двадцать минут, поэтому ветка авто-обновления в
   `public/app.js:236` в жизни не срабатывает. «Повторять больше нечего» достижимо только при
   пустом наборе. Тесты проверяют, что продукт с такими состояниями справится, а не то, что
   человек до них дойдёт. Это вопрос к продукту, а не к тестам.
3. **Подозрение на лимит ответа.** `lib/prompts.js:61` даёт уточнению `maxTokens: 2000`, а на
   Opus 5 рассуждение включено по умолчанию и считается в тот же лимит. Приложение такой случай
   обрабатывает (`lib/claude.js:71`), то есть по `specs/` ведёт себя правильно, но человек может
   увидеть ошибку вместо вопроса. Проверяется только живым вызовом.
4. **Модель вернула не двенадцать слов, а меньше.** Продукт принимает любой непустой набор
   (`server.js:68`). В `specs/` такого сценария нет: описан только пустой ответ (2.10). Это
   пробел в требованиях, а не расхождение с ними.
