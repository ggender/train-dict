# Тесты: требование → тест

Тесты написаны по требованиям из `specs/` и работают с приложением снаружи: открывают
страницу в браузере, печатают, жмут кнопки, закрывают вкладку, перезапускают сервис.

```sh
npm test          # всё: экран, HTTP и расчёт сроков. Без сети, без ключа, ~15 секунд
npm run test:unit # только расчёт сроков
npm run test:e2e  # только экран и HTTP
```

## Как устроен стенд

| Файл | Что делает |
|---|---|
| `test-harness/app.js` | Поднимает приложение во временной копии проекта: рабочее состояние и `.env` тестам недоступны |
| `test-harness/model-stub.js` | Подставная модель — отвечает как Anthropic API, но без сети и без денег |
| `test-harness/state.js` | Заготовки сохранённого состояния: «вчера», «просрочено», «карточка вот-вот» |
| `test-harness/fixtures.js` | Выдуманные ответы модели и наборы слов |

Времени на сервере снаружи не подкрутить, поэтому «вчера» и «просрочено» делаются датами
в самих данных, а не подменой часов.

## Чего тесты не проверяют

1. **Качество ответов живой модели.** Подставная модель отвечает тем, что в неё положили,
   поэтому проверить, действительно ли модель задаёт один вопрос за раз и подбирает живые
   примеры, нельзя. Тринадцать таких сценариев закрыты на границе: тест смотрит, какое
   задание продукт отправляет модели и доходит ли туда задача человека целиком. Если правило
   из `specs/` пропадёт из задания — тест покраснеет; если модель начнёт нарушать правило,
   которое ей передали, — нет.
2. **Два сценария расписания зафиксированы искусственно.** Состояния «карточка вернётся
   меньше чем через десять минут» (4.8) и «повторять больше нечего» (4.9) обычным путём
   в продукте не достигаются: окно захода втягивает всё, что вернётся в ближайшие двадцать
   минут, а срок всегда есть, пока есть невыученные слова. Тесты подкладывают такое состояние
   напрямую — они проверяют, что продукт с ним справится, а не то, что человек до него дойдёт.
3. **Возврат к оставленной странице (4.10) имитирован.** Спрятать вкладку в headless-браузере
   нельзя: страницы в нём остаются видимыми, и вторая вкладка первую не прячет. Тест шлёт
   то же событие, которое в этот момент шлёт браузер, и отдельно проверяет меткой на странице,
   что она не перезагрузилась. Что событие приходит при настоящем возврате — на совести браузера.
4. **Испорченный набор проверяется механически.** Тесты ловят слово, оставшееся в пропуске,
   слово в подсказке и неполный набор. Однокоренные слова в подсказке так не поймать — это
   по-прежнему обещание, которое даётся модели в задании (3.3, граница).

## Почему в основном e2e, а юнитов всего три

Юниты взяты только там, где экран доказывает правило косвенно. Проверено мутацией: если
сжать окно захода с двадцати минут до одной, **не падает ни один e2e-тест** — провал
всё равно возвращается в заходе, потому что назначается через минуту. Красным становится
только юнит. Дневную норму, наоборот, ловят пять e2e-тестов сразу.
